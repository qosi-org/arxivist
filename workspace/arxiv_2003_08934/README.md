## What this paper does

NeRF represents a static 3D scene as a single neural network (an MLP) that
maps a 5D input — a 3D point in space plus a 2D viewing direction — to a
color and a density at that point. To render an image, camera rays are
marched through the scene, the network is queried at points along each ray,
and classical volume-rendering math composites those queries into a pixel
color. Because that whole process is differentiable, the network can be
trained directly from a handful of ordinary photos with known camera poses —
no 3D supervision needed — and the result is a compact (~5MB), continuous
3D scene representation that can render sharp, photorealistic novel views,
including realistic reflections and other view-dependent effects.

## Implementation Assumptions

The following choices were not fully pinned down by the paper text; see `sir.json` (Stage 1
output) for the complete list with confidence scores and alternatives considered.

- **Framework**: TensorFlow 2.x — the paper states "We implement our model in Tensorflow"
  (Appendix A); this repo uses modern TF2 eager/`tf.GradientTape` rather than the original TF1
  graph API.
- **Exact training-step count**: paper reports a 100k-300k range; `configs/config.yaml` defaults
  to 250k, `configs/full_paper.yaml` uses 300k (upper end, closest to Table 1).
- **Learning-rate decay formula**: paper states lr goes from 5e-4 to 5e-5 "exponentially... over
  the course of optimization" without giving the exact decay-rate formula; this repo uses
  `lr(step) = lr_init * (lr_final/lr_init)^(step/num_training_steps)`.
- **Weight initialization**: unspecified in the paper; this repo uses Keras' default (Glorot
  uniform), matching common community practice for this architecture.
- **TinyNeRF consumer-hardware preset** (`configs/tiny_consumer.yaml`, `--tiny` flag): inspired by
  the official TinyNeRF demo notebook (bmild/nerf: `tiny_nerf.ipynb`), which is **not part of the
  peer-reviewed paper**. Its exact hyperparameters could not be verified from the paper text
  alone; the values used here (single shallow MLP, no hierarchical sampling, downsampled images,
  ~5k steps) are the well-known community defaults, kept fully isolated from the paper-faithful
  default path so the two are never silently conflated.

## Reproducibility Notes

- **Known deviations from paper-exact quality**: `configs/config.yaml`'s defaults (`half_res:
  true`, 250k steps) prioritize a faster default run over exact Table 1 fidelity; use
  `configs/full_paper.yaml` for the closest match to the reported numbers.
- **Low-confidence / stub components**:
  - `nerf.data.dataset.DeepVoxelsDataset` is a **STUB** — the DeepVoxels pose-file format is not
    described in this paper's text; implement against the official DeepVoxels release before
    reproducing Table 3.
  - `preprocess_llff.py` runs COLMAP's sparse reconstruction but does **not** reimplement LLFF's
    final `poses_bounds.npy` packaging step (undocumented at the equation level in the paper);
    use the official LLFF conversion script for that last step.
  - LPIPS evaluation depends on `lpips-tf2`, a less-standardized TF2 port of the original PyTorch
    LPIPS metric; if unavailable, `evaluation/metrics.py::ImageMetrics.lpips()` returns `None`
    rather than crashing, and PSNR/SSIM remain available.
- **Reproducibility mechanics**: `nerf.utils.config.set_global_seed()` seeds Python, NumPy, and
  TensorFlow, and is called at the top of every entrypoint; `training.deterministic: true` in any
  config additionally enables TensorFlow's deterministic-ops mode (slower, debugging only).
- Full equation-by-equation provenance (which paper section/equation each code path implements,
  and the confidence score behind every non-trivial choice) is in `sir.json` and
  `architecture_plan.json`, generated by ArXivist Stages 1-3 ahead of this repository.
